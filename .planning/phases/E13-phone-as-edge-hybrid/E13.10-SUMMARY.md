# Phase E13 Plan 10: Admin Runtime Badge (Pi / Phone) in Edge Devices Panel

## One-liner
Runtime badge (Phone/Pi/Unknown) added to the central admin's Edge Devices table.

## Context
Built as part of wave E13 (Phone-as-Edge-Hybrid). The central admin panel now shows whether each paired device is running on a Pi or Phone chassis, using the `runtime` column already present on `EdgeDevice`.

## What was built

- **`app/Http/Resources/EdgeDeviceResource.php`** — New API resource for `EdgeDevice` model exposing `runtime` field with null-coalescing default to `'pi'` for backward compatibility with legacy devices that predate the runtime column.
- **`app/Http/Controllers/Api/Admin/EdgeDeviceController.php`** — Refactored `index()` and `update()` to use `EdgeDeviceResource` instead of the inline `$this->deviceResource()` array builder, so runtime is included in all API responses without duplication.
- **`resources/js/Components/admin/EdgeDevicesPanel.svelte`** — Added `Type` table column with conditional badge rendering:
  - `phone` → purple badge "Phone"
  - `pi` → orange badge "Pi"
  - anything else → gray badge "Unknown"
- **`Device` TypeScript interface** — Extended with `runtime: "pi" | "phone" | "dev" | string` field.

## Decisions Made

- Null runtime defaults to `'pi'` in the PHP resource (not the Svelte template). This ensures legacy devices that have never reported their chassis type still display "Pi" rather than "Unknown" — matching the intended behavior described in the plan.
- The Svelte component's `{:else}` branch (gray "Unknown") only triggers for truly unrecognized runtime values, keeping the display consistent across layers.
