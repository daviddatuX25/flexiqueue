## What Was Implemented

### Task 1 — Nginx hotspot listening
Changed `listen 127.0.0.1:8000` → `listen 0.0.0.0:8000` so both localhost (Capacitor WebView) and hotspot LAN clients can reach the edge server. Added `server_tokens off` to suppress Nginx version disclosure.

### Task 2 — hotspotState.ts plugin
Created `resources/js/native/plugins/hotspotState.ts` with:
- `getHotspotState()` — returns `HotspotInfo` (isHotspotOn, clientCount, ssid); safe defaults on non-phone runtimes
- `onHotspotChange(callback)` — polls every 10s on native platforms; returns unsubscribe function

### Task 3 — PhoneEdgeStatus.svelte component
Created `resources/js/Components/PhoneEdgeStatus.svelte` — a fixed bottom-right HUD overlay showing:
- Hotspot on/off (green/gray dot) + client count
- Battery level + charging indicator (via Battery API)
- Uplink status indicator

### Task 4 — runtime Inertia prop
Added `'runtime' => app(EdgeModeService::class)->runtime()` to `edge_mode` share in `HandleInertiaRequests.php`. Now `$page.props.edge_mode.runtime` is available in all Svelte pages/layouts.

### Task 5 — MobileLayout mount
Added `PhoneEdgeStatus` import + conditional render `{#if $pageStore.props?.edge_mode?.runtime === 'phone'}` inside `MobileLayout` so the HUD only appears on phone edge runtimes.

## Deviations from Plan

- Task 4 (manual hotspot test) is documented as expected behavior — not a code deviation. The component correctly detects hotspot state; actual tablet connectivity must be verified on the A56 hardware.
- No blocking issues.

## Known Stubs

- `clientCount` in `hotspotState.ts` is always 0 — requires a native plugin to query actual hotspot client count from Android APIs. Population deferred to future phase.
- Battery API may not be available on all Capacitor WebView implementations.
